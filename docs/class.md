# Ключевые отношения в системе
## 1. Неизменяемые объекты Git (GitObject)
* Blob, Tree, Commit наследуются от GitObject
* Идентифицируются по хешу содержимого
* Никогда не изменяются после создания

## 2. Структура репозитория
* Repository содержит Branch (композиция)
* Каждая Branch указывает на Commit
* Repository содержит Index для staging area
* Index содержит StagedFile (файлы готовые к коммиту)

## 3. Древовидная структура
* Tree содержит TreeEntry (композиция)
* TreeEntry ссылается на Blob или другой Tree
* Commit ссылается на корневой Tree

## 4. Use Cases (сценарии использования)
* Каждая команда VCS реализуется отдельным Use Case
* Use Cases зависят от Repository и других сервисов
* Реализуют бизнес-логику системы

## 5. Инфраструктурные зависимости
* Repository использует FileSystemService, ObjectStorage, Serializer
* Use Cases для удалённых операций используют RemoteTransport
* Разделение на слои позволяет тестировать и заменять реализации

## 6. Конфигурация и пользователи
* RepositoryConfig содержит настройки репозитория
* Remote определяет удалённые репозитории
* User представляет автора коммитов
