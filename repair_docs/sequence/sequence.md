# Диаграмма последовательностей
## Ключевые участники процесса:
Контролёр качества - инициатор процесса, обнаруживает и регистрирует дефекты

Система учёта дефектов - центральный компонент, координирующий весь процесс

Диспетчер - распределяет автомобили по ремонтным зонам

Бригадир - планирует ремонты и назначает исполнителей

Ремонтник - выполняет ремонтные работы

Внешние системы (ERP/MES) - предоставляют данные об автомобилях и производстве

База данных - хранилище всех данных системы

## Основные этапы взаимодействия:
### 1. Регистрация дефекта
* Контролёр обнаруживает дефект и сообщает системе
* Система запрашивает данные об автомобиле из внешних систем
* Контролёр заполняет подробную информацию о дефекте
* Система сохраняет данные и уведомляет диспетчера

### 2. Диспетчеризация
* Диспетчер запрашивает статус ремонтных зон
* На основе доступности назначает зону и место для ремонта
* Система обновляет статусы и уведомляет бригадира

### 3. Планирование ремонта
* Бригадир изучает детали дефекта
* Запрашивает список доступных ремонтников с нужной квалификацией
* Назначает конкретного исполнителя
* Система уведомляет ремонтника о новом задании

### 4. Выполнение ремонта
* Ремонтник регистрирует начало работы (при необходимости)
* Получает детали задания из системы
* Фиксирует начало ремонта (время, место)
* Параллельно запрашивает запчасти и документацию
* Фиксирует процесс и результаты ремонта
* Сообщает системе о завершении работы

### 5. Проверка качества
* Контролёр получает уведомление о готовности
* Проверяет качество выполненного ремонта
* Принимает решение: принять или вернуть на доработку
* В случае принятия - дефект закрывается, место освобождается
* В случае отклонения - процесс возвращается к этапу ремонта

### 6. Отчётность
* Система автоматически рассчитывает метрики
* Генерирует отчёты для различных участников
* Обновляет статусы в реальном времени
