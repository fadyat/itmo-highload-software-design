# Описание проблем с диаграммой классов
## Структурные проблемы
### 1. Избыточные и вычисляемые поля
ShiftReport.totalRepairs - можно получить из количества repairDetails

ShiftReport.totalRepairTime - должно быть вычисляемым полем, а не хранимым

RepairZone.numberOfPlaces и RepairZone.freePlaces - вычисляются из списка repairSpots

RepairPlace.isOccupied - должен определяться по наличию текущего ремонта

### 2. Проблемы с типами данных
Роли сотрудников - представлены строкой, вместо иерархии классов или enum

Цвет автомобиля - строка вместо класса Color или enum

Локация дефекта - строка вместо геометки или enum этапа производства

### 3. Избыточные связи и дублирование
Repair.repairTeam - избыточно, команда определяется через работника или бригадира

Двойное хранение в Car - и defectList, и repairHistory (ремонты уже содержат информацию о дефектах)

Несколько путей получения одной информации (например, команда ремонта через работника, место, зону, команду)

### 4. Семантические проблемы отношений
Repair - слишком много связей (many-to-many-to-many-to-many), создаёт сложность

Car.defectList и Car.repairHistory - нарушение инварианта: ремонт без дефекта или дефект без ремонта

Order - содержит цвет как строку, но заказ может быть на несколько цветов?

## Недостающие сущности
### 5. Отсутствующие классы
CarModel - для хранения информации о модели автомобиля

Color - для типизированного представления цвета

Специализированные роли сотрудников - вместо строки role

## Проблемы с отчётностью
### 6. Конструкторы отчетов
QualityControlReport - не хватает связи с ремонтами для расчёта статистики

AccountingReport - непонятная структура, нет связи с сотрудниками

### 7. Флаги доступности
Worker.available - проблематично поддерживать в актуальном состоянии

RepairPlace.isOccupied - аналогичная проблема, особенно для коротких интервалов

## Общие архитектурные проблемы
### 8. Нарушение нормальных форм
Очень сильная связанность между компонентами

Повторение одной информации в нескольких местах

Отсутствие единого источника истины для многих сущностей

### 9. Противоречивые паттерны
Использование строк там, где нужны типизированные объекты

Смешение плана производства и фактического производства

Нечёткое разделение ответственности между классами
